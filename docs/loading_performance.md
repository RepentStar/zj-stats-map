# 图表加载性能记录

更新日期：2026-10-27。用户已确认完成功能验收；本次后续维护调整图表模块加载方式，并通过自动化测试、数据校验和生产构建依赖检查验证修改。

## 加载策略

首页加载 OpenLayers 地图、数据与控件，以及 `ol-echarts` 叠加层所需的 ECharts 依赖，用于总量气泡与产业饼图。请求图表窗口时，入口通过 `Promise.all` 并行加载共享运行模块 `explore.js` 与 `loadType.js` 中对应的类型模块，避免先下载运行模块再请求类型模块。窗口复用首页已加载的依赖。

| 请求 | 类型模块 | 专用组件 |
|---|---|---|
| 人口占比 | `types/pie.js` | PieChart |
| 城市排行、产业增加值 | `types/bar.js` | BarChart、GridComponent |
| 历年趋势 | `types/line.js` | LineChart、GridComponent、MarkLineComponent |
| 产业占比 | `types/radar.js` | RadarChart |

SVG 渲染器、图例、工具提示、无障碍、标题、Graphic 图形组件及标签布局由共享运行模块注册，Graphic 用于雷达小多图的城市名称与坐标范围说明。ECharts 自身对重复注册去重，浏览器模块缓存复用成功加载的模块，多个窗口可并发请求。所有模块加载完成后才创建图表，读取共享最新年份与城市范围；窗口若已关闭则跳过初始化。加载失败继续提供重新加载页面入口，渲染失败仍支持窗口内重试。

## main 原有生产产物对比

环境：当前项目 Vite 8.3.5、ECharts 6.1.0。单位为十进制 kB，以下统计压缩前的 JS 文件字节数。首次图表统计所需全部静态依赖并去重，扣除首页已加载部分，包含图表引擎和共享组件，不能只看类型入口文件大小。

| 场景 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---|
| 首页 JS | 334.92 kB | 335.98 kB | 增加约 1.06 kB，用于类型加载映射及预加载依赖 |
| 首次打开人口占比，额外 JS | 609.50 kB | 506.19 kB | 减少约 17% |
| 首次打开排行或产业堆叠，额外 JS | 609.50 kB | 549.15 kB | 减少约 10% |
| 首次打开趋势，额外 JS | 609.50 kB | 572.52 kB | 减少约 6% |
| 首次打开产业雷达，额外 JS | 609.50 kB | 514.67 kB | 减少约 16% |

以上为合并地图展示 PR 之前 main 的构建记录。按类型拆分会增加请求数量，收益主要体现在仅使用部分图表类型的场景；用户打开全部类型时仍需加载全部模块。模块拆分后的公共依赖由 Vite 自动提取，没有调高体积提示阈值。

## 合并地图展示 PR 后

地图气泡与产业饼图依赖 `ol-echarts`，因此首页包含 ECharts 相关依赖，不能再沿用原来“首页无 ECharts”的结论。保留按类型加载的窗口入口，构建检查仍验证窗口入口及类型入口没有被首页静态引用；该检查不代表 ECharts 内部图表实现完全延迟加载。

| 场景 | JS 原始体积 | gzip 合计 |
|---|---:|---:|
| 首页 | 1545.46 kB | 499.56 kB |
| 首次人口占比窗口，额外 | 8.42 kB | 3.62 kB |

本次构建最大 JS 单块约 1149.41 kB，触发 Vite 默认 500 kB 体积提示；构建成功。为保留 PR 的地图叠加功能，未调整体积提示阈值。

上述数字是构建产物体积，不是实测网络耗时；实际下载量和速度取决于服务器压缩、缓存和网络状况。检查脚本同时报告各文件独立 gzip 后的合计，仅作传输体积参考。

## 复现与检查

```bash
npm test
npm run build:check
```

- `npm test`：覆盖既有数据、图表和联动逻辑；新增五类图表在独立进程中的首次注册与 SVG 渲染、并发加载及未知类型错误检查，避免其他类型的预注册掩盖缺失组件。
- `npm run build:check`：先校验数据并构建，生成 `dist/.vite/manifest.json`；随后检查首页不静态依赖图表运行模块及类型模块、共享模块不提前引入类型、单个类型不加载其他类型，输出去重后的 JS 体积。

合并后验证结果为 56 项 JavaScript 测试、13 项 Python 测试通过，数据覆盖率 1210/1210，构建和依赖检查通过。以上体积随代码、依赖及打包版本变化，以重新执行命令的输出为准。
